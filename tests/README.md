# Tests

Two kinds of checks, both run in CI (`.github/workflows/ci.yml`).

## Static checks (a few seconds)

```sh
tests/check_syntax.sh
```

Runs `node --check` on `app/js/**`, `app/sw.js`, `dev/**`, `notifier/server.js` and `folders/*.js`, then parses every GraphQL query of the Suwayomi connector. The `graphql` package is installed in `tests/graphql/` only (the repo root has no `package.json`). Requires Node 22 and network access for `npm install`.

The folders tests import `yauzl`: run `npm ci --omit=dev` in `folders/` once before them (CI does). The notifier tests start the real notifier (`notifier/server.js`), which needs `web-push`: run `npm ci --omit=dev` in `notifier/` first (CI does). The two push tests that send for real (`integration_notifier_push.mjs`, and `integration_notifier_robustness.mjs`) also need `openssl` to make a throwaway certificate.

## End-to-end tests (~4 minutes for both scripts)

Headless browser tests (Playwright for Python) that start the demo server (`node dev/mock-servers.mjs`) on ports 8391-8397, 8411-8412, 8431-8438, 8441-8442 and 8481-8485 and drive the app. The folders suites also start the real folders service (`node folders/server.js`, ports 8461-8470) on a library generated by `dev/make-folders-fixture.mjs`, and the demo server relays `/folders/` to it (`FOLDERS=`), as nginx does; they need `npm ci --omit=dev` in `folders/`.

Each script prints `PASS`/`FAIL` lines, then `ALL PASS` or `SOME FAILED`. The exit status is 0 only if every check passed and no exception occurred; demo servers are always stopped.

| Variable | Effect |
| --- | --- |
| `CHROME_PATH` | Use this Chrome/Chromium executable instead of Playwright's bundled Chromium. |
| `SHOTS_DIR` | Save screenshots to this directory (created if needed). No screenshots when unset. |

Make sure ports 8391-8397, 8411-8412, 8431-8438, 8441-8442, 8451-8459, 8461-8470, 8481-8485 and 8499 (kept unused on purpose) are free before running (a stale demo server makes checks fail).

### What the push tests cannot cover

- **Delivery through a real push service** (FCM, Mozilla, Apple). The notifier's sending is checked against a local HTTPS fake that decrypts the message with the device key (`integration_notifier_push.mjs`); nothing is sent to a real service, and no real browser receives it.
- **`pushManager.subscribe` in headless Chromium.** It fails here with `AbortError: Registration failed - permission denied` even with the permission granted, because the browser has no push service to register with. `e2e_push.py` therefore replaces `PushManager.prototype.subscribe` and `getSubscription` with a stub in the page (init script, test only); the app, the notifier and the service worker are real.
- **A click on an operating-system notification.** It cannot be produced without a display. The real service worker receives a synthetic `NotificationEvent` (with `WindowClient.focus` and `Clients.openWindow` recorded, since the browser grants those only to real clicks), and `unit_sw_push.mjs` runs the handler with fake clients.
- **iOS / Safari**: no WebKit here. On iPhone, push exists only for the app added to the home screen; the panel's "not supported" state is checked by removing `PushManager`, nothing more.
